# СДЕЛАНО · Интеграционный релизный кандидат PR #50

Не публиковать и не объединять без отдельного разрешения владельца. Это документация для изолированной Draft-ветки, а не инструкция менять \`main\`.

## Автоматизированный мобильный маршрут

\`tests/release-mobile-journey.mjs\` проверяет в одном состоянии приложения при ширинах 320 и 390 px (в каждой матрице Chromium/Firefox/WebKit):

1. Пустой кошелёк, выключенное облако, реальное создание и выполнение семи задач через форму, правильные последовательные награды и дневные бонусы: 95 XP / 50 монет.
2. Покупка шарфика за заработанные 50 монет: один предмет и одно списание, повторная покупка отклоняется без дополнительных потерь.
3. Подтверждение одной **имитированной уже завершённой** фокус-сессии (+5 XP, −1 энергия); повторная награда блокируется. Тест НЕ ждёт реальные 15 минут и НЕ подтверждает правильность хода реального таймера — это покрывают отдельные тесты.
4. Перезагрузка: XP 100, монеты 0, энергия 4, 1 покупка и 7 наград за задачи остаются неизменны.
5. Скачивание реальной полной JSON-копии v2 из UI и импорт в независимый профиль браузера. Проверка всех 7 задач, фокуса, магазина, экипировки и кошелька после новой загрузки.
6. Нет горизонтального переполнения после восстановления, ошибок JS или побочных облачных сетевых операций; скриншоты источника и восстановленного профиля.

Изоляция осуществляется через чистые Playwright BrowserContexts; реальный \`main\`, пользовательские данные и Supabase не затрагиваются.

## Ручная приёмка на физическом телефоне

- Проверь размеры, форму записи, фокус на поле ввода, доступность клавиатуры, читабельность наград.
- Заверши настоящее дело: короткий кивок и звук не мешают следующему действию; отключи звук и включи настройку «Уменьшение движения».
- Пройди **реальные** 15 минут фокуса, скрой и верни вкладку: не должно быть награды за скрытое время; однократное подтверждение даёт +5 XP.
- Проверь магазин при достаточных монетах, повторное нажатие, смену экипировки, перезагрузку.
- Скачай резервную копию и проверь восстановление в **отдельном тестовом профиле**, предварительно сохранив свои данные. Не удаляй текущие задачи ради теста.
- Проверь отсутствие неожиданных экранов с данными и запроса входа в облако. Облако по умолчанию выключено.

## Отдельные релизные блокеры

CI подтверждает только автоматизированные сценарии. Реальные устройства, деградация сети, 15 минут живого таймера, миграция существующей БД, проверка RLS двумя пользователями и решение о выпуске — отдельные ручные проверки. Когда облако выключено, SQL-миграция не нужна для локального релиза.


## Управляемое время для проверки настоящей логики таймера

`tests/focus-clock-e2e.mjs` запускает `focus.js` с контролируемыми `performance.now()` и `setInterval` через Playwright Clock. В отличие от READY-фикстуры проверяется сам UI-процесс:

- старт, 30 секунд видимого фокуса;
- скрытие на 10 минут — 0 дополнительного времени; возврат не возобновляет фокус без нажатия;
- пауза ещё на 2 минуты — 0 дополнительного времени;
- 14:59 суммарного видимого времени не дают права на награду;
- ровно 15:00 дают кнопку «Забрать +5 XP», но XP не начисляются сами;
- одно подтверждение даёт +5 XP, -1 энергию, повторный запрос ничего не выдаёт, перезагрузка сохраняет состояние.

Это ускоренная виртуальная проверка логики по API браузера, **а не реальное ожидание 15 минут**. Не заменяет ручной контроль на смартфоне, в том числе уход в фон и ограничения таймеров ОС.


## Необязательное системное уведомление о паузе

- Кнопка «Уведомление о паузе» по умолчанию **выключена**. Разрешение браузера запрашивается только при явном нажатии.
- Если фокус был активен и браузер свёрнут, одна системная карточка сообщает «Фокус на паузе · Осталось MM:SS». Значение не уменьшается, потому что фокус действительно стоит на паузе.
- Нет регулярных напоминаний, автономной активности лисёнка, фоновых таймеров, запросов на сервер, Web Push-подписки, отправки текстов задач.
- Возврат, продолжение, отмена и выключение функции закрывают устаревшее уведомление; повторный `visibilitychange` не выдаёт новую карточку.
- Устройство и браузер могут не показать уведомление. На Android нужен HTTPS и разрешение OS/браузера; в iOS поддержка зависит от установки веб-приложения на главный экран. Если внешний предпросмотр блокирует Service Worker, сначала проверяем UI и статус паузы, затем функциональность на собственном домене.
- **Это локальное уведомление при событии в открытой вкладке, не настоящий удалённый push при закрытом браузере.** Таймер и XP не затрагиваются.

Новая регрессия `tests/focus-pause-notification.mjs` проверяет отсутствие автоматического запроса разрешения, включение/отключение по клику, одно уведомление после реальной паузы, таймер в тексте и отсутствие начисления XP (Chromium/Firefox/WebKit, 320/390 px).

**Безопасность предпросмотра:** на общих доменах `raw.githack.com` и `gist.githack.com` кнопка системных уведомлений недоступна — браузер выдал бы разрешение всему внешнему домену, а не конкретной ветке. Проверка реальной ОС должна проводиться только на доверенном домене приложения.

- При уже разрешённом уведомлении после перезагрузки воркер подготавливается заранее, пока вкладка видима. Не появляется повторных запросов разрешения: это устраняет гонку регистрации с заморозкой Android-вкладки.
- Дополнительная регрессия: включить уведомления → уйти в фон → вернуться → перезагрузить страницу → воркер зарегистрирован заранее → снова фокус и сворачивание дают ровно одну карточку без повторного permission prompt.
